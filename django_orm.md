# Django ORM, Migrations, and Transactions

# 1. What is Django ORM?

ORM stands for:

```text
Object Relational Mapping
```

ORM is a feature in Django that allows us to interact with the database using Python code instead of writing SQL queries.

Without ORM:

```sql
SELECT * FROM student;
```

With ORM:

```python
Student.objects.all()
```

Django automatically converts ORM queries into SQL queries.



# Why Do We Use ORM?

Benefits:

* No need to write SQL manually
* Database-independent
* More readable
* Less chance of SQL Injection attacks
* Faster development


# ORM Flow

```text
Python Code
      ↓
Django ORM
      ↓
SQL Query
      ↓
Database
```

Example:

```python
Student.objects.filter(age=20)
```

Django converts it to:

```sql
SELECT * FROM student
WHERE age = 20;
```


# Example Model

```python
from django.db import models

class Student(models.Model):
    name = models.CharField(max_length=100)
    age = models.IntegerField()
```

# 4. What Are Aggregations?

Aggregation means performing calculations on multiple rows and returning a single result.

Examples:

* Count
* Sum
* Average
* Maximum
* Minimum


Suppose Student table contains:

| Name | Marks |
| ---- | ----- |
| Sri  | 90    |
| John | 80    |
| Ravi | 70    |


## Count

```python
from django.db.models import Count

Student.objects.aggregate(
    Count("id")
)
```

Result:

```python
{'id__count': 3}
```


## Sum

```python
from django.db.models import Sum

Student.objects.aggregate(
    Sum("marks")
)
```

Result:

```python
{'marks__sum': 240}
```


## Average

```python
from django.db.models import Avg

Student.objects.aggregate(
    Avg("marks")
)
```

Result:

```python
{'marks__avg': 80}
```


## Maximum

```python
from django.db.models import Max

Student.objects.aggregate(
    Max("marks")
)
```

Result:

```python
{'marks__max': 90}
```


## Minimum

```python
from django.db.models import Min

Student.objects.aggregate(
    Min("marks")
)
```

Result:

```python
{'marks__min': 70}
```


# What Does Aggregate Return?

Aggregate returns:

```text
One Summary Result
```

Example:

```python
Student.objects.aggregate(
    Avg("marks")
)
```

Result:

```python
80
```

One value for the entire table.


# 5. What Are Annotations?

Annotations perform calculations for each row and add a new field to every record.

Think of it as:

```text
Aggregate
    ↓
One result

Annotation
    ↓
Result per row
```


Example Models:

```python
class Student(models.Model):
    name = models.CharField(max_length=100)

class Exam(models.Model):
    student = models.ForeignKey(Student,
                                on_delete=models.CASCADE)
    marks = models.IntegerField()
```

Suppose:

| Student | Marks |
| ------- | ----- |
| Sri     | 80    |
| Sri     | 90    |
| John    | 70    |


Annotation Query:

```python
from django.db.models import Sum

Student.objects.annotate(
    total_marks=Sum("exam__marks")
)
```

Result:

| Student | Total Marks |
| ------- | ----------- |
| Sri     | 170         |
| John    | 70          |


Example:

```python
Student.objects.aggregate(
    Avg("marks")
)
```

Result:

```text
80
```

Example:

```python
Student.objects.annotate(
    total=Sum("exam__marks")
)
```

Result:

```text
Sri → 170
John → 70
```


# 6. What is a Migration File?

A migration file contains instructions about database changes.

Whenever a model changes:

```python
class Student(models.Model):
    name = models.CharField(max_length=100)
```

and later:

```python
class Student(models.Model):
    name = models.CharField(max_length=100)
    age = models.IntegerField()
```

Django needs to update the database.

Migration files tell Django how to make those changes.


# Creating Migrations

```bash
python manage.py makemigrations
```

Example Output:

```text
Migrations for 'myapp':
0001_initial.py
```


# Applying Migrations

```bash
python manage.py migrate
```

Django executes the necessary SQL queries.


# Example Migration File

```python
from django.db import migrations, models

class Migration(migrations.Migration):

    operations = [
        migrations.CreateModel(
            name='Student',
            fields=[
                ('id', models.BigAutoField()),
                ('name', models.CharField(max_length=100))
            ]
        )
    ]
```


# Why Are Migrations Needed?

Without migrations:

```text
Model Changes
     ❌
Database Not Updated
```

With migrations:

```text
Model Changes
      ↓
Migration
      ↓
Database Updated
```

Benefits:

* Version control for database schema
* Easy database updates
* Team collaboration
* Rollback support


# 7. What Are SQL Transactions?

A transaction is a group of SQL operations treated as a single unit of work.

Example:

Bank Transfer

```text
Account A → Deduct ₹1000
Account B → Add ₹1000
```

Both operations must happen together.


Without Transactions

```text
Deduct ₹1000
❌ Server Crash
Add ₹1000 Not Done
```

Money is lost.

With Transactions

```text
Deduct ₹1000
Add ₹1000
```

OR

```text
Nothing Happens
```

No partial updates.


# Transaction Properties (ACID)

## A - Atomicity

All operations succeed or all fail.

## C - Consistency

Database remains valid.

## I - Isolation

Transactions do not interfere with each other.


## D - Durability

Once committed, changes remain permanent.


# SQL Example

```sql
BEGIN;

UPDATE account
SET balance = balance - 1000
WHERE id=1;

UPDATE account
SET balance = balance + 1000
WHERE id=2;

COMMIT;
```

If something fails:

```sql
ROLLBACK;
```


# 8. What Are Atomic Transactions?

Atomic means:

```text
All or Nothing
```

Either:

```text
Everything succeeds
```

OR

```text
Everything fails
```

No partial changes.


# Django Atomic Transactions

Django provides:

```python
from django.db import transaction
```

Example:

```python
from django.db import transaction

with transaction.atomic():

    sender.balance -= 1000
    sender.save()

    receiver.balance += 1000
    receiver.save()
```


# What Happens If Error Occurs?

Example:

```python
with transaction.atomic():

    sender.balance -= 1000
    sender.save()

    raise Exception()

    receiver.balance += 1000
    receiver.save()
```

Result:

```text
Everything Rolled Back
```

Database remains unchanged.


# Why Use Atomic Transactions?

Use when multiple database operations depend on each other.

Examples:

* Bank transfers
* Order placement
* Payment processing
* Inventory updates
* User registration involving multiple tables
